# Architecture

How a LuminoseHF session is put together, and why. Read this before changing the trial loop, trial selection, scoring, the live plots, odour delivery or settings loading.

## The layout

```
LuminoseHF/
  LuminoseConstants.m        rig configuration (luminose_config.yaml beside it)
  +lhf/                      code shared by the protocols (below)
  protocols/luminose_hf_<name>/
    luminose_hf_<name>.m     the session: setup, START, trial loop, cleanup
    HelperFiles/devices/     soft-code handler, DMD handler (laser for powercal)
    HelperFiles/gui/         GUIparams_* (setting declarations), LuminoseParameterGUI_*
  dmd/, olfactometer/, laser/, gui/   DMD player, olfactometer, irradiance calibration, GUI widgets
  calibration/               calibrate_*.m (lhf.cal.run from the command line), read_powermeter, rigStages
  tests/                     hardware-free test suite (docs/testing.md)
```

Protocols: `goNogo`, `powercal` (goNogo with a laser power on each trial that shows a pattern, drawn from the design's own irradiance list, so a one-value list gives a fixed power; its CS+ and CS- designs are its own, see D11), `2AFC`, `MTS` (match-to-sample) and `sleep` (test pulses, no behaviour).

### The shared package, `+lhf`

The package is `lhf`, not `luminose`: the protocols keep a global variable named `luminose`, which would hide a package of the same name.

| Code | What it owns |
|---|---|

| `lhf.scoreTrial`, `lhf.Outcome` | The one definition of a trial's outcome and response, and the stored outcome codes |
| `lhf.nextTrialType`, `lhf.trialPolicy`, `lhf.responseBias` | Trial selection and bias correction |
| `lhf.random` | The session's seeded random stream |
| `lhf.responseTime` | Response time of one trial |
| `lhf.plot.*` | The live-plot window (`createFigure`) and its panels: `outcome`, `accuracy`, `reward`, `responseTime`, `encoder`, `power` (percent correct per irradiance; a fourth row with `createFigure('WithPower', true)`, used by powercal) and `analog` (the last trial's four Flex analog channels, read from the session's `_ANLG.dat` by `lhf.bpod.readTrialAnalog`; a last row with `createFigure('WithAnalog', true)`, used by goNogo, powercal, 2AFC and MTS) |
| `lhf.olf.*` | Odour delivery through the `olfactometer` package (D16): `startWorker`, `waitWorker`, `deliver` (soft-code side), `close` (cleanup), `resolve` (which valves), `drawRows` (a trial's rows, drawn as it is prepared), `sequenceDuration` (how long a row plays) |
| `lhf.mergeSettings`, `lhf.settingsHistory` | Loading a saved settings file into the current declarations |
| `lhf.patternFolder`, `lhf.patternFileType`, `lhf.patternDesign` | Where pattern designs are saved, the name a type's files carry, and one row's design (or none) |
| `lhf.selectedDesign` | The design of the pattern row chosen for this trial, or [] |
| `lhf.patternTiming` | Each pattern row's exposure and frame count, set from its design at startup |
| `lhf.patternDuration`, `lhf.stimDuration` | How long a design plays on the DMD; how long a cue or stimulus lasts, this trial's or its longest row (D13) |
| `lhf.laser.*` | Optional laser control: `open`/`close` (only with Laser control ticked), `draw` (a trial's power from its pattern's design), `onSoftCode` (code 13), `options`, `describe` (the pattern table's laser column), `setpoint` (cached calibration) |
| `lhf.stopRecord` | Why a session ended (`Data.StoppedReason`) |
| `lhf.report.*` | The end-of-session report: `write`, `summary`, `summaryImage` |

Each is placed against where its neighbours actually are, else their default sizes |
| `lhf.spotImage` | A design's spots as one DMD frame |
| `lhf.subjectName` | The Bpod subject selected (the report, the fiducial's animal) |

Still per protocol (they differ too much to share safely): the state machine (`PrepareStateMachine`), setting declarations (`GUIparams_*`), the parameter GUI, the DMD handler, the sound and rotary-encoder setup.

## The session

1. **Setup.** `LuminoseConstants`, the olfactometer worker (`lhf.olf.startWorker`, whose warm-up runs while the GUI is open; `lhf.olf.waitWorker` after START), the settings (`GUIparams_*` defaults, then `lhf.mergeSettings` with the saved file), the parameter GUI.
2. **START.** `onCleanup(@cleanup)` is registered; the session seed is drawn (`lhf.random('init')`) and stored; the first trial type is chosen; the live-plot window opens; devices are set up.
3. **Trial loop.** For trial *k*: sync the GUI → choose and prepare trial *k*+1 and send it with `RunASAP` → wait for trial *k*'s data (`getTrialData`) → start *k*+1 → record *k* (events, settings, `lhf.scoreTrial`, sniff, encoder) → update the plots (newest trial only) → one `drawnow` → save every 5 trials.
4. **End.** The loop ends when all trials ran, when the operator stops (`handle_pause_condition`), or on an error; each records `Data.StoppedReason`.
5. **Cleanup** (`onCleanup`, so it also runs after an error or Ctrl+C): DMD closed, data and settings saved, the report written, `RunProtocol('Stop')`, `BpodSystem` cleared from the base workspace.

## Decisions

**D1. The next trial is prepared while the current one runs; there is no repeat-on-error.** Trial *k*+1 is built and sent with `RunASAP` during trial *k*, so it starts with no gap. Its type is therefore chosen before trial *k*'s outcome is known: the recorded data end at trial *k*−1. A repeat-on-error rule could only repeat trial *k*−1's type on *k*+1, splitting the session into two interleaved chains, and in 2AFC/MTS it repeated the wrong trial's type. It was removed (2026-09-29); old settings files drop `RepeatOnError` with a note. Bias correction keeps reading recorded responses: a 20-trial window one trial late is harmless. Habituation alternation reads the running trial's type (`runningType`), which is known. Two guards around Bpod (from 2026-10-07, `lhf.bpod`): `BpodTrialManager` polls the serial port with a 10 ms timer whose callback holds the trial manager, so a session stopped mid-trial left it polling and stealing the next reader's bytes (the sniff calibration's `RunStateMachine` then waited forever); every protocol stops such timers as it starts and in `cleanup`, and the sniff calibration before its trial (`stopStrayTrialTimers`; it refuses to run during a session or twice at once). Bpod's Flex I/O viewer writes a batch larger than one sweep past its buffer whenever MATLAB was busy longer than a sweep, after which every redraw warns (`XDataYData`); the protocols open it fresh (`startFlexViewer`: `startAnalogViewer` reused an open window and its broken buffer) only when the Sniff panel's **Analog viewer** box is ticked (unticked by default; checked before each trial, `showFlexViewer`; the data are recorded either way and the live plots show the last trial's channels), and reset an overflowed buffer after each trial (`repairFlexViewer`), never from a timer (a 0.25 s repair timer, 2026-10-14 to 10-21, wrote into `BpodSystem` while the trial loop did, the pattern suspected in the MATLAB crashes; a trace that overflows stays blank until the trial ends). The rotary encoder module reads its serial port from a timer of its own, which interrupted the trial loop's reads of the same port; the loop pauses it for them (`readEncoder`, from 2026-10-20). The trial manager and the encoder object are each held by their own timer's callback, so they outlived every session: a stopped trial-manager timer and a running encoder capture timer per session, and about 75 MB more memory each; from 2026-10-21 each session deletes both as it ends (`release`, through an `onCleanup`), which runs their own destructors. Bpod_Gen2 itself is unchanged.

**D2. One scoring function.** `lhf.scoreTrial` is the only place a trial is scored. The loop stores its result in `Data.TrialOutcome` and `Data.TrialResponse`; the plots, bias correction and the report read those fields and never look at states themselves. Before this, the accuracy plot scored 2AFC Right trials with go/no-go's rule (reaching the ITI without punishment counted as correct), and the outcome plot's no-response marks could never appear for go/no-go. In choice tasks only licks during `GetResponse` count as the response, so a lick during the cue is not a choice.

**D3. Outcome codes are data.** `lhf.Outcome`: 0 incorrect, 1 correct, 3 no response. Never renumber or reuse one.

**D4. Plots keep their own state.** Each `lhf.plot.*` function keeps its line handles and running values in its axes' `UserData`, adds only the newest trial on update, and leaves the redraw to the loop's single `drawnow`. No globals or persistent variables, so they can be tested with no Bpod and replayed for the report.

**D5. Odour delivery runs on one warmed-up worker.** The soft-code handler resolves the valves in the client (where `S` is valid; a worker has its own globals) and hands only the resolved data to a one-worker process pool through `olfactometer.AsyncDelivery` (the worker side is `olfactometer.internal.serve`; until 2026-10-05 `lhf.olf.worker`). The pool is created before the parameter GUI opens (`lhf.olf.startWorker`) and the DAQ session is warmed up on it while the GUI is open, because `daq("ni")` in a fresh worker process can take a minute; after START, `lhf.olf.waitWorker` waits for the warm-up and fails loudly if it failed, before any trial. If the pool is gone, `lhf.olf.deliver` warns and skips rather than letting `parfeval` open a new pool mid-session. Worker errors go to `<data file>_olfactometer_errors.txt`, because nothing collects `parfeval` errors; a request the package refuses (a clean-air valve, a duty above 1) is logged there by `lhf.olf.deliver` and never thrown. A duty of 0 is the bottle's own, filled in from the rig's tables (read once by `startWorker`) before sending, and `S.GUI.delivered_dutyCycles` records the duty sent; before 2026-10-05 the worker read the tables by bare name on every delivery and the zeros were recorded. `lhf.olf.close` keeps the deliveries in `Data.Olfactometer`; the pool stays open, and the worker now rebuilds its olfactometer when the config changes.

**D6. One seed per session.** `lhf.random('init')` draws a seed, stored in `Data.RandomSeed`. Trial types, the ITI order and odour rows draw from its stream; MATLAB's global stream is seeded from it too (for pattern rows, random spots and the barcode). To repeat a session's draws, put its seed in `S.RandomSeed` in the settings file: it is used once and cleared. Draws on the global stream can still differ if soft codes arrive in a different order.

**D7. Settings are merged, not overwritten.** `GUIparams_*` builds the defaults from nothing; `lhf.mergeSettings` then applies the saved file: declarations (`GUIMeta`, `GUIPanels`, `GUITabs`) always from the defaults, saved values kept, renamed settings moved and retired ones dropped (`lhf.settingsHistory`), and a value of the wrong kind or an out-of-range menu choice replaced by the default. Every change is printed at startup and stored in `Data.SettingsNotes`. To rename a setting, add it to `lhf.settingsHistory`; never reuse a retired name.

**D8. Every session records why it ended.** `Data.StoppedReason` (`lhf.stopRecord`): `completed`, `operator`, `error` (with the message and stack) or `unknown` (cleanup found none: a setup error or Ctrl+C). An error once Bpod has been stopped is the stop's consequence, not a crash: `operator`, with the error kept.

**D9. Every behaviour session ends with a report.** `lhf.report.write`, from cleanup after the data are saved: `<data file>_report.md` (session, performance per trial type, water, response time, settings changed during the session, settings-file notes) and `<data file>_summary.png` (the live panels redrawn over the whole session). It never throws. Sleep sessions have no report.

**D10. The config file is found beside the code.** `LuminoseConstants()` reads `luminose_config.yaml` from the folder holding `LuminoseConstants.m`, so the repository works wherever it is cloned. The paths inside the YAML are still the rig's.

**D11. powercal's stimuli are designs with defaults, not hard-coded.** powercal keeps its CS+ and CS- designs in the shared `dmd/Patterns` folder under their own file names, `designed_powercalCSplus_*` and `designed_powercal_*` (`luminose.dmd.typeFileNames`, read through `lhf.patternFileType` by the Pattern Designer, the DMD handler and the loaders), so goNogo's `CSplus`/`CSminus` designs never reach it; cue and opto designs stay shared. At startup `loadPowercalDesigns` loads only powercal's files. Until 2026-10-01 they were in a subfolder, `dmd/Patterns/powercal`, under the type names. Both CS+ and CS- default to Pattern. Defaults until something is designed there: CS+ row 1 is blank, no spots for 80 ms (`blankMs`: nothing is projected, no soft code or laser power is sent, but the stimulus lasts 80 ms, D13; its table row shows an 80 ms exposure, one frame, like CS-; save a blank with another Tick in the Pattern Designer to change it), and CS- row 1 is a single spot at the DMD centre for 80 ms, 0.12 mm wide. Both last `defaultStimMs`, so the response window opens 80 ms after the sniff on both trial types. A design's spot size is set in the Pattern Designer (**Spot side**) and saved with it (`r_px`); a design opens at its own size, a new one at the rig default (`luminose.dmd.spotSide`). Until 2026-10-02 powercal set it for all its designs with `S.GUI.dmdSpotSide` on the Task tab. A pattern row with no design shows nothing: `PrepareStateMachine` sends no soft code for it (8, 9 or 10) and draws no laser power, while the trial keeps its mask, sniff wait and timing. Laser power is set per design (D12). Before 2026-09-30 CS- was a hard-coded spot (`CentralSpotSide_um`, `CentralSpotDur_ms`, now retired) that ignored the designer.

**D12. The laser is optional, and its power belongs to each pattern.** Every behaviour protocol has a **Laser control** checkbox on the Trials tab (on the Task tab until 2026-10-02) (ticked by default in powercal, unticked elsewhere). Unticked, `lhf.laser.open` connects nothing and no power is ever set, so a session runs with the laser unplugged; the DMD's pin 8 still gates emission at whatever power the laser was left at. Ticked, a laser that does not connect stops the session before trial 1 with a message to untick it. Each stimulus pattern design carries its own irradiance list and draw weights, set in the Pattern Designer (a table, one row per irradiance with its probability, rescaled to sum to 1 as the pattern table's Prob and saved as the draw weights, beside the calibrated range from `irradianceCalibration`; it appears for types whose `S.GUIMeta.patternSel_<type>.LaserOptions` is set: CS+/CS-, Left/Right, Template/Sample; a design saved without them uses `LaserDefaults`). The parameter GUI's pattern table shows each row's list read-only in a **Laser mW/mm2 (prob)** column (`lhf.laser.describe`; `none` for a row with no spots, which sets no power). A trial showing a pattern draws one irradiance from that design (`lhf.laser.draw`), converts it with the power calibration (cached per session) and queues it. The calibration is full-field, and the DMD is not lit evenly, so it is scaled by `laser.spotGain` in `luminose_config.yaml` (spot irradiance / full-field irradiance, measured 2026-10-01 at 2.348 for a 57×57-mirror spot near the centre): irradiances mean irradiance in that spot, and the calibrated range is about 1.1–34 mW/mm²; soft code 13 in the trial's first state, `SetLaserPower`, sets it. One power per trial: MTS uses the Template's design, or the Sample's on a Non-match trial whose only pattern is the Sample. Every power set is logged to `<data file>_laser_log.txt`. The designer refuses an irradiance outside the calibration.

**D13. A cue or stimulus lasts as long as what it shows.** There is no cue or stimulus duration setting. `ShowCue` and the `DeliverStim` states (MTS: `DeliverStimTemplate`, `DeliverStimMatch`) are timed by `lhf.stimDuration` from the kind chosen in the Task tab: a **pattern** by the drawn row's design as the DMD plays it once, `ceil(max(onset_ms + dur_ms) / tickMs)` frames of the row's exposure (`lhf.patternDuration`, the sequence `DMDPatternPlayer` builds; a row with no design lasts 0; a blank design, saved in the Pattern Designer with no spots (it asks first) or powercal's default CS+, shows nothing, no DMD sequence or laser power, for its `blankMs`, the Tick it was saved with, so its length is set like any design's); an **odour** by its sequence, one olfactometer slot (`preSequenceTime + pulseTime + postSequenceTime` from the config) per odour in the drawn row (`lhf.olf.sequenceDuration`); **light** and **sound** by the `Duration (s)` in their own panel (`LightDuration_<type>`, `SoundDuration_<type>`; a sound is generated at that length when the session starts). So the next state, the response window, starts as the stimulus ends. For the timer to match what is delivered, the odour rows are drawn as the trial is prepared (`lhf.olf.drawRows` into `BpodSystem.PluginObjects.NextOdourRow`) and handed to the soft-code handler (`SelectedOdourRow`) after `getTrialData`, as the DMD handler's `advance` hands over its sequences: the next trial is prepared before the running one's soft codes arrive (D1). The time from the sniff to the response window therefore differs between rows of different lengths. MTS has no cue state: its cue starts with the Template, so its cue has a sound `Duration` only. A row with no spots, no design or a blank, sends no soft code in any protocol: neither its start code (8, 9, 10) nor the halt (11), which goes out at `GetResponse` only when the trial projected a stimulus pattern (since 2026-10-05; before, goNogo, 2AFC and MTS sent them regardless, and 2AFC and MTS sent 11 on every trial). The mask and the sniff wait stay. The GUI's trial-structure preview shows each type's longest row. Until 2026-10-02 `Cue Duration (s)` and `Stim Duration (s)` (`CueTime`, `StimTime`) timed every kind: a longer pattern was halted by soft code 11 at `GetResponse`, a shorter one left the DMD blank, and an odour's `StimTime` was refilled by the GUI from the longest sequence.

**D14. A pattern starts at the sniff onset, if Sniff Trigger is ticked.** With **Sniff Trigger** (Trials tab, Sniff panel; ticked by default), a pattern stimulus waits in `GetSniff` (MTS: `GetSniffTemplate`, `GetSniffMatch`) for the sniff detector's onset event, `Flex1Trig1`; unticked, it starts as soon as the cue ends. Odour, light and sound stimuli never wait for a sniff. The sniff is always detected on a falling signal, as an inhalation drives it (`SniffDetector.risingEdge` false, also for the calibration button). Until 2026-10-02 a **Rising Edge** checkbox (`SniffRising`) could flip it for a hand test, and was ticked by default in goNogo and powercal.

**D15. A pattern row's exposure is its design's tick.** The DMD shows each frame of a row's design for the row's exposure (`S.GUI.patternExposure_<type>`, in us; the pattern table's **Exposure (ms)** shows it in ms), so it must be the tick the design was made with, or the pattern plays faster or slower than designed. The Pattern Designer sets the exposure and frame count when it saves, and every protocol sets them from the designs at startup (`lhf.patternTiming`, after the settings are loaded), so a settings file saved before a design changed cannot carry an older exposure. The column is read-only. A blank design is one frame of its `blankMs`. Until 2026-10-05 a saved settings file kept its exposures (the designs' were read only without one), and the column could be edited: a design saved with a 10 ms tick could run at an older 80 ms exposure, eight times slower.

**D16. Device drivers live in their own repositories.** A device's driver, its simulated device, its tests and its docs are a package in its own repository beside DMDController and SpinCam in `paths.matlabFolder`, written to the standard of DoricLED: the OBIS laser is `obis` ([OBISLaser](https://github.com/SainsburyWellcomeCentre/OBISLaser)), the Zaber stage `zaberstage` ([ZaberStage](https://github.com/SainsburyWellcomeCentre/ZaberStage)) and the Hamamatsu camera `hamacam` ([HamamatsuCam](https://github.com/SainsburyWellcomeCentre/HamamatsuCam)), all since 2026-10-05; before, `laser/LaserModel.m`, `zaber/ZaberModel.m` and `camera/CameraModel.m`. The calibrations use the shared stage and camera (`lhf.device`); the Z focus calibration narrows Z's limits to its scan and puts them back (D20). Every axis in `zaber.axes` needs a `safe_um: [min max]`, the range it may move in without the equipment hitting anything (`-Inf`/`Inf` for an end of the travel; on the rig X is open, Y is at least 35 mm, Z at most 30 mm; `calibration/rigAxisOptions.m`; an axis without it does not connect): it becomes the stage's `SafeLimitsUm` (ZaberStage), which is locked while connected, so a script narrowing `LimitsUm` to its scan cannot widen it, and `home()` is refused when the home end lies outside it. Z is `zaber.axes.z` (`zaber.axisIndex` is gone: it named axis 1, which is X). The config's fallback YAML reader (`parseYAMLBasic`) reads nested blocks at any depth, `[a, b]` lists and `{key: value}` maps; before 2026-10-05 it stopped at three levels and returned lists as text. This repository keeps only what is particular to the rig and the protocols: soft codes, queues and logs (`lhf.laser`), the irradiance at the sample (`irradianceCalibration`: the DMD field area and `laser.spotGain` on top of `obis.Calibration`) and the config file. `LuminoseConstants.devicePackages` lists the repos; `addDevicePackages` puts each repo's root, and none of its subfolders, on the path (their `tests/` would shadow this repo's names) and records each package's `version()` in `luminose.packageVersions`, saved with the session. `lhf.laser.open` refuses a power above `laser.maxPower_mW` through `obis.Laser.MaxPowermW`, and every command now waits for the laser's `OK`: `LaserModel` never read the replies. The olfactometer is `olfactometer` ([NIDAQOlfactometer](https://github.com/SainsburyWellcomeCentre/NIDAQOlfactometer), since 2026-10-05; before, `olfactometer/OlfactometerModel.m` and `lhf.olf.worker`); its sequences are the original's sample for sample (a test there compares them), and the rig's bottle tables and config stay here. `CameraModel` started its camera with an immediate trigger and `TriggerRepeat = Inf`, logging frames to memory between snapshots; `hamacam` uses a manual trigger. SpinCam replaces Bonsai, removed 2026-10-05 (`bonsai/`, the `bonsai` config section, the sleep protocol's launch). Since 2026-10-06 each device package also has its own control panel (`hamacam.app`, `zaberstage.app` for every axis, `obis.app`, `DMDController.app`), and those panels are what controls the devices: LuminoseHF builds no device controls and has one object per device, `lhf.device(name)`, which the panels (opened by the parameter GUI's Camera / Stage / Laser / DMD buttons under START, `gui/DeviceButtons.m`, `lhf.devicePanel`), the Pattern Designer, the session (`lhf.laser.open`, `DMDPatternPlayer`), `lhf.stagePosition` and the calibrations (`lhf.cal.run`, D20) all use. There is no second owner to clash with: what a panel does the rest sees. While a session runs (START to its cleanup) the Laser and DMD panels are view only (`lhf.lockDevicePanels`, their `lock`/`unlock`; also one opened mid-session through `lhf.devicePanel`): they show the session's power, emission and projection, but a press cannot change them; the laser's Stop (emission off) stays usable. The Camera and Stage panels stay usable. The Laser panel opened here also shows the power out of the objective for its setpoint (`obis.app`'s `'Calibration'`, from `dmd/power_calibration.csv`, measured with every DMD mirror on, so a partial pattern puts less on the sample), and its **Pulse** row pulses emission from MATLAB timers for setting up; locking the panel for a session stops any pulsing. The Camera panel opened here names each frame it saves with that power (hamacam's `NameTagFcn` = `lhf.laser.powerTag`): `_sample5.1mW`, `_setpoint170mW` outside the calibration, `_10Hz20pct` added while pulsing, `_laserOff` with emission off, nothing with no laser connected. It reads what the laser last accepted and sends no command. Its Save to folder is the subject's `<dataFolder>/<subject>/luminose_hf_widefield`, beside the subject's Bpod protocol folders (`lhf.cam.subjectFolder`, made and set by `lhf.cam.useSubjectFolder`): the Bpod subject when the panel opens or is brought to the front and at START, the Pattern Designer's animal when it is set. Browse still picks any folder until the next of those. Connect and Disconnect are the panels'; the rest leaves a device connected when done (the session turns the laser's emission off and halts the DMD). `DMDController.DMD.connect` does nothing when already connected, so a script's `connect()` cannot re-open the shared DMD under its sequences.

**D17. The Pattern Designer's canvas is the camera.** Spots are placed on the Hamamatsu camera's own panel (`hamacam.app`, opened through `lhf.devicePanel('camera')`, live or a capture), where the DMD will light the tissue: the designer (`gui/PatternDesigner.m`, opened by `PatternDesignerGUI` from the pattern tables) draws the DMD field's outline, each spot's square and the fiducial marks on the panel's image (`CameraApp.setOverlay`) and takes the presses on it (`setImageClickFcn`; Draw and Measure on the panel keep theirs). A click becomes a DMD pixel through the camera-DMD calibration, and each spot's square is drawn by mapping its corners back, so what is drawn is what will be lit, turned and scaled as the camera sees it; spots are still kept and saved in DMD pixels, so saved designs, `lhf.patternDesign` and `DMDPatternPlayer` are unchanged. The calibration (`calibration/calibrate_camera_dmd.m`) projects one spot at a time on a 6 x 5 grid, finds each in the camera (`lhf.cam.spotCentroid`) and fits an affine map (`lhf.cam.fitRegistration`); one spot per frame, so no point can be matched to the wrong one, and the map holds the rotation (about 47 deg), the scale (about 1.365 camera px per DMD px), any mirror and the offset that the earlier XY scripts each measured only in part. Since 2026-10-06 its camera side is in full-sensor, unbinned pixels (`registration.space = 'sensor'`; `hamacam.Camera.frameToSensor`/`sensorToFrame`, pixel k spanning k +/- 0.5), so a calibration made once holds at any subarray or binning the camera panel is set to; earlier files were full frame at binning 1, the same pixels (`lhf.cam.loadRegistration` says so in `note`). The newest `camera_dmd_*.mat` is used; without one spots cannot be placed (the window says to run the calibration; a saved design can still be retimed and saved). The designer's window keeps the spot controls (mode, nSpots, Randomize, the overlay layer, the table, Tick, Spot side, the timeline, the laser table, Save) and **Show on DMD**: ticked, the design (`lhf.spotImage`, all spots at once) is projected on the rig's DMD and again at every change, so the light can be checked against the drawn squares; **DMD all on** (in the fiducial column, and turned on by **Place mark**) lights every mirror instead, to see the whole field while finding and marking the fiducial; the two exclude each other; unticked or closed, the DMD halts; after START the session's `DMDPatternPlayer` owns the DMD and it is refused. The designer opens the Laser and Stage panels with the camera's (from 2026-10-06: light to image the tissue by, and Z to focus; **Device panels** brings the three back; opening a panel connects nothing), and without a calibration the camera panel still opens, to look and focus. Closing the designer takes its drawing off the camera panel; the three panels stay open. The fiducial is per animal (`lhf.subjectName` by default), in a column that unfolds to the right: **Place mark** and a click on the camera image put a mark on a landmark, **Save fiducial** captures an averaged frame and adds it with the mark to `calibration/fiducials/<animal>.mat`; the first one saved is the reference, never replaced, shown as a red crosshair. Marks are kept in full-sensor camera pixels, which change neither with the readout nor when the DMD path is recalibrated; each entry also records the readout (`roi`, `binning`). Until 2026-10-06 the designer had a DMD-shaped canvas of its own with a camera column beside it (`gui/DesignerCameraPanel.m`: live, capture, exposure and contrast of its own, the frame warped into DMD space by `lhf.cam.canvasMap`/`toCanvas`), all removed. Until 2026-10-05 `calibration/align_sample_fiducial.m` kept one rig-wide mark position, with no frame and no animal.

**D18. The stage aligns the sample to the animal's reference.** **Align to reference** in the designer's fiducial column (`lhf.cam.align`) registers what the camera sees on the animal's reference frame and moves the Zaber X, Y and Z axes until they match, so a pattern lands on the same tissue session after session. Registration uses the whole image, not the fiducial mark (`lhf.cam.register`): both frames are cropped to the DMD field, downsampled and flat-fielded (divided by a heavy blur of themselves, since the illumination is fixed to the camera and would otherwise pull the answer to no shift), then phase correlation (`imregcorr`) gives the shift and a confidence (its peak; a blank view scores about 0.03, tissue 0.5-0.9, and below `minPeak`, 0.1, nothing moves); its angle, too coarse below a degree or two, is refined by trying angles within 1 deg and keeping the best match. A stage move turns into an image shift through `C` (2x2, camera px per um), measured by `calibration/calibrate_stage_camera.m` (move X and Y by +/-100 um, register each, fit; `lhf.cam.fitStageCamera`), so the stage axes' directions and their rotation on the camera need no assumptions. The loop: X/Y to within 10 um (each move -inv(C) * shift, at most `maxStep_um`); Z stepped across +/- `zSearch_um`, each plane approached from below, to the plane whose image correlates best with the reference (a parabola through the best three); then X/Y to `tolerance_um` at a finer scale. The first move waits for a confirmation showing it; pressed again the button stops between moves; no move may leave a box of `maxTravelXY_um`/`maxTravelZ_um` around where it started. Rotation cannot be undone by X/Y: it is reported, with a warning to re-seat the animal above `rotationWarn_deg`. An aligned frame is added to the animal's file with the result and the stage positions. The axes are three `zaberstage.Stage`s on one port (`calibration/rigStages.m`, `zaber.axes` in the config), sharing a transport (`SharedTransport`, ZaberStage); an axis with `reversed: true` counts the other way (`Reversed`, ZaberStage D8: mirrored in software, the controller unchanged), as X does on the rig (X is axis 1, Y 2, Z 3), and `C` absorbs the sign, so reversing an axis means rerunning `calibrate_stage_camera.m`. Settings: `zaber.alignment` (`LuminoseConstants.alignmentDefaults`). Not while a session runs, and only with the camera read out as the reference was (the same subarray and binning: frames are compared pixel for pixel; the designer says which to set); the frames are cropped to the DMD field's box in the frame read out. The fiducial column's STAGE block (from 2026-10-05) shows X/Y/Z (**Read**, and after each move it makes) and **Go to reference X/Y**: X and Y move, together and stoppable, to the position saved with the reference (its `stageUm`, else the newest session's), after a confirmation and only within each axis's limits (both targets are checked before either moves); Z stays for alignment to find, so nothing approaches the objective. It brings back tissue that is further off than alignment's travel box after the animal is re-seated; a fiducial records a stage position only when the stages are connected (press Read before Save fiducial).

**Targets (2026-10-13).** Points of interest on the tissue (glomeruli) are marked in the designer's TARGETS section: **Mark targets**, clicks on the camera image, names and ticks in the table, **Save targets** (`calibration/targets/<animal>.mat`, `lhf.cam.saveTargets`). They are kept in full-sensor px of the animal's *reference* fiducial frame, not of the session they were marked in, so they come back in any session: **Locate** captures a frame and registers it on the reference (`lhf.cam.register` on the DMD field, no stage move) and `lhf.cam.mapPoints` carries the targets into this view (shift and rotation about the crop centre); a successful Align to reference runs it too, and Align or Go to reference X/Y forget it (the view moves). Marking needs a located view, so a mark is converted back to the reference. Unlocated targets are drawn dashed where they were in the reference. A click within a spot's half-width (at least 10 px) of a located target puts the spot on its centre, **Spots on targets** puts one on each ticked one, and the saved design's meta file names each spot's target (`spotTargets`). Locating needs the current image to look like the reference (same light and focus, the same readout); a low peak is refused rather than guessed.

**D19. A session and its preparation can be recreated from the data alone.** At START every protocol stores `Data.Setup` (`lhf.recordSetup`): the commit, uncommitted diff and untracked source files of every repository it ran (`lhf.provenance`: a commit alone does not say what ran), the config as text and as a plain struct (the `LuminoseConstants` object in `Data.luminose` may not load once the class changes), copies of the calibrations in force (`lhf.calibrationSnapshot`: `calibrate_power` overwrites `dmd/power_calibration.csv`, newer calibrations replace older ones, and the odour duty cycles come from tables that can be edited), the Zaber position at START (`lhf.stagePosition`, through the Pattern Designer's stages when it holds the port) and the subject's newest fiducial entry. Each trial records what it drew and showed through `Actions`, which is assigned to the trial it was prepared for: the pattern and odour rows, and each pattern as the DMD was given it (`DMDPatternPlayer.prepareSpots` returns it), so random spot positions and edited or replaced designs are not lost. Logs that were shared between sessions (the DMD log in `%TEMP%`) are written beside the data with the trial on each line (`lhf.sessionFile`, `lhf.runningTrial`), and odour deliveries are kept per trial in `Data.OdourDeliveries`. Every calibration saves `lhf.provenance` with its results. `lhf.recreate(dataFile, folder)` writes a session back out as files: settings with the session's seed, the designs shown, the config, the calibration tables, each repository's patch and a README with the commits, the stage position and the fiducial. Added 2026-10-05; older sessions have none of this.

**D20. Calibrations are run from one window, with their settings in view, and are used only once saved.** Until 2026-10-06 each calibration was a script with its settings written into it (the Z scan's centre and range, the camera-DMD grid and spot size, the stage step, the power setpoints from the CSV), devices opened by the script, no way to stop it but Ctrl+C, and its result saved, and so used, at once. The Calibration window (`gui/CalibrationApp.m`, the **Calibrate** button beside Camera / Stage / Laser / DMD, `lhf.devicePanel('calibration')`) lists the rig's calibrations (`lhf.cal.catalog`: Camera - DMD, Stage - camera, Z focus, Laser power), says for each what it does and what to set up first, and shows its settings in a table: pre-filled with what it last ran with (`setpref('LuminoseHF', 'calibration_<id>')`), else the defaults (the config's where it has one: exposure, averaging, `zaber.zStep_um`, the CSV's setpoints); each edit is checked (`lhf.cal.settings`). **Run** runs it (`lhf.cal.run`) on the rig's one object per device (`lhf.device`), each camera frame shown on the Camera panel; **Stop** ends it at the next step. However a run ends, it puts back what it changed: the camera's exposure and averaging, the stage limits a scan narrows, X/Y/Z where they started; the DMD halts and the laser's emission is off. Its result is plotted (`lhf.cal.plot`) with anything worth checking (spots not found, a fit worse than its threshold, a scale far from the config's, a weak registration, the focus at an end of the scan, saturated frames, setpoints with no power at the sample), and nothing uses it until **Save** (`lhf.cal.save`), which writes the same files as before, now with the settings they ran with, so `lhf.cam.loadRegistration`, `loadStageCalibration` and `irradianceCalibration` read them unchanged (the newest is the one in use); **Discard** drops it. Saving a power calibration asks first, since every session converts irradiance with `dmd/power_calibration.csv`, and keeps the CSV it replaces (`power_calibration_previous_<stamp>.csv`). The power calibration now reads the power at the sample from a PM100D at each setpoint (`lhf.cal.powerMeter`, Meter PM100D) instead of values typed into the CSV (still used with Meter none). **Saved results** lists every earlier run, the one in use first, and plots any. Not while a session runs. The scripts `calibration/calibrate_*.m` remain, running the same with the last settings and saving at once. Retired with it: `calibrate_xy_checkerboard`, `_lines`, `_plus`, `_singlepixel` and `_white` (each measured part of what Camera - DMD fits), `align_sample_fiducial` (the Pattern Designer's fiducial, D17), `dmd/test_dmd_custom`, `test_dmd_mat`, `test_dmd_calibration_grid` and `generateCalibrationGrid` (the DMD panel's test patterns and designed-pattern view), `rigCamera`, `rigStage` and the designer's old `canvas_background*.png`.

## Rules that follow

- Anything that decides from trial outcomes must accept that the running trial is not yet recorded (D1).
- Score in `lhf.scoreTrial`, nowhere else (D2).
- New per-trial plots go in `lhf.plot`, keep state in `UserData`, update from the newest trial and do not call `drawnow` (D4).
- Draw random numbers from `lhf.random()` (D6).
- Declare settings in `GUIparams_*`; rename or retire them through `lhf.settingsHistory` (D7).
- Add a test for anything added to `+lhf` (docs/testing.md).
- Anything a trial draws or shows goes in its `Actions` (D19); anything in force for the whole session goes in `Data.Setup`; logs go beside the data (`lhf.sessionFile`).
- Device code that is not particular to this rig or its protocols goes in the device's own repository (D16), with a simulated device this suite can use.
